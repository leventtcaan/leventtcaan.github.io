Inside Next Call

How one weekly call gets made

  1. 01

    It reads the week

    Weigh-ins, logged meals, finished workouts, progress photos. Nothing is decided yet.

  2. 02

    Rules look at the trend

    A deterministic engine checks the numbers against the goal. In this case: −0.3 kg a week for three weeks, not toward the goal.

  3. 03

    One decision comes out

    Calories go from 2,050 to 1,800. The same inputs always give the same answer, so the logic can be tested like any other code.

  4. 04

    The AI puts it into words

    A language model writes the explanation the user reads. It doesn't get to change the number.

Next Call

Solo · iOS · 2026

On the App Store since Nov 2026

A weekly coaching app for lifting and diet. It looks at your training, food, weight and photos, and once a week it makes one call on what to change.

How it's built

Java and Spring Boot on the backend, split into modules with Spring Modulith. The React Native client is generated from an OpenAPI contract, so the app and the server work from the same definition. It runs in Docker on a VPS I set up and maintain.

Decisions I'd defend

  • Rules decide, the model explains. A coaching number should be reproducible and testable. Wording is where a language model helps.
  • Modules, not services. One person, one deploy. Clear seams if it ever has to be split.
  • Contract first. The API is written as an OpenAPI spec before the code, and the mobile client is generated from it.

What's missing: real users. That's the next step, not a footnote.

Senior design project · team of 3 · 2026–2027

Reads a packaged food's label from a photo and checks it against sourced rules for the user's health conditions. When the rules or the data don't cover a case, it says so instead of guessing.

My part is the architecture and the Python label pipeline: text cleanup, ingredient matching (E-codes, Turkish plural forms, fuzzy matching) and rule evaluation from a versioned rule table. Submitted to TÜBİTAK 2209-A.

How I work

Write the decision down first

Before a non-trivial change I write a short decision record: the options, the one I picked and why.

Agents type, I keep the judgment

I build with AI coding agents every day. My own attention goes to boundaries, contracts, tests and reading what got written.

Boring and testable wins

If a behaviour can't be tested, I don't trust it yet. That's the whole reason the coaching logic is rules and not a prompt.
